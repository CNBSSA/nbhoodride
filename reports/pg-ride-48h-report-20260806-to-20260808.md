## Shipped

### 1. Shared-schedule double-discount — P1 (#190, `c80c02b`)
The 2nd member of a shared ride (the join that activates the 30% group discount) was
being charged **~51% off** instead of 30%, with `originalFare` overwritten to the
already-discounted amount. Fixed so the ride that triggers activation settles the
discount exactly once, consistent with the organizer.
**Live-verified:** organizer / 2nd joiner / 3rd joiner all land at exactly 30% off
(was 30 / 51 / 30 before the fix).

### 2. Top-up payment safety — P0 #2 + #3 (#192, `881d5e7`)
Two paths where Stripe was charged but the wallet was never credited:
- The idempotency claim was committed **before** the wallet credit, so a failed
  credit left the claim standing and every retry returned a stale "already
  processed" success (uncredited).
- No server-side fallback if the client never called `/topup/confirm` — a killed
  app / dropped network after Stripe succeeded meant the charge stuck.

**Fix:** release-on-failure of the claim + a `payment_intent.succeeded` top-up branch
that credits via the same dedup key the confirm endpoint uses (mutually idempotent).

### 3. Payment reconciliation queue — P0 #1 (visibility) (#194, `b83def9`)
Failed card settlements were invisible outside server logs — a driver could complete
the work and never be paid, with no fleet-wide surface (`getRidesAwaitingPayment` is
per-driver). Added a durable `settlement_failed` payment status, a fleet-wide admin
queue, and the **Reconciliation** tab in the admin dashboard.

### 4. Idempotent settlement retry — P0 #1 (action) (#196, `798485a` — 8 commits)
Turned the visibility-only queue into an actionable one with a **Retry settlement**
button, made genuinely safe to re-run:
- **Driver paid at most once** — advisory-locked `creditDriverEarningsOnce`
  (proven: 5 concurrent credits → exactly one wins).
- **Rider never double-charged** — overage settlements are **refused** (they'd
  recompute the split against current balance) and routed to manual reconciliation
  (HTTP 422, "Manual only" in the UI).
- **Tip preserved** — persisted atomically inside `completeRide` so a settlement
  failure can't strand it.
- **Short-circuit** when the driver was already credited; best-effort release of any
  lingering Stripe hold; self-healing concurrency claim lock.

## Notable find (production gap closed mid-review)

`addVirtualCardBalance` had shipped to `main` **non-atomic**: PR #191 was merged at
its pre-atomicity commit (the merge's 2nd parent is `881d5e7`, not the atomicity
commit `35e71d7`), so the top-up release-on-failure fix (P0 #2) had been running
**without the atomicity it depends on**. Cherry-picked `35e71d7` back into #196 —
balance + ledger now commit together again. (Lesson: a GitHub merge can land a PR at
an earlier commit than the branch tip if push/merge timing lines up; verify merge
SHAs against branch tips.)
